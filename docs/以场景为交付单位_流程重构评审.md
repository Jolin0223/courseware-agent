# 以场景为交付单位：视频互动课件流程重构评审

2026-09-14｜状态：重构建议，尚未实施主流程。基于当前源码、本地运行页面、用户批注，以及 9 月 12—13 日的 HyperVideo 实测记录。本次重新访问体验站加载超时，未把历史记录当作今天的功能复测。

## 1. 判断

**建议改成“整课结构 → 场景工作台 → 整课交付”。同一场从内容规划、素材准备、生成到成品始终在同一个位置，老师围绕这一场判断和修改。**

后台仍然需要依次准备参考图片、音频、视频和互动页面；这些依赖由系统执行。教师界面不必跟着每种素材换一张卡、再重新找所属场景。

但不建议要求老师依次给 12 场分别确认“目标、素材、分镜”三次。默认批量准备、集中审阅、批量生成；有问题才进入某一场修改。单场确认和单场生成作为可选操作。

当前 Demo 的数据一开始已经有 12 个场景，其中 5 场包含视频，共使用 6 个视频资源（含环境视频）。它并不是最后才重新规划出 12 场，但界面把这些场景的材料分散到多轮卡片里，造成了这种感觉。新流程要修正这一点。

## 2. 当前字段为何不好用

当前代码由 `createFixture` 装入示例，悟空内容映射既有场景数据；其他主题使用简化模板。`purpose / interaction / next` 直接显示为“教学内容 / 学生如何参与 / 怎样进入下一环节”，并不是接入真实规划服务后从这次需求推导出的结论。[源码：示例数据](../src/data/videoCourseware/fixtures.ts)、[场景编辑器](../src/components/VideoCourseware/VideoWorkflowCard.tsx)。

“建立西游识字主题与开始动机”解释设计意图，却不能约束要生成的内容；“在同一入口启动声音”属于实现安排；“进入下一环节”大多能从场景顺序推导。把这些内容都作为大文本框，老师既难理解，也不知道修改后会得到什么。

| 当前项 | 新方案 | 老师实际可改的内容 |
| --- | --- | --- |
| 教学内容 | 本场内容：一句可判断结果的说明 | 展示的主题、剧情、知识点或问题，例如“悟空在火焰山受阻，解释为什么需要借扇” |
| 学生如何参与 | 仅有互动时显示“互动内容”，给具体内容与小样 | 问题、选项、正确答案、拖动对象与目标、提示、答对/答错反馈；观看视频不出现此项 |
| 怎样进入下一环节 | 普通顺序自动处理 | 默认不让老师填写；分支或特殊课堂节奏才展示对应规则 |
| 画面与人物动作 | 放进具体分镜的“画面描述” | 谁出现、在哪里、做什么、画面应保留什么；提供可直接编辑的完整描述 |
| 谁来说＋一大段台词 | 每条台词单独绑定说话人及使用位置 | 改文字、换角色、换音色、试听或换真实音频，同场允许多人对话 |

内容必须有依据：明确要求来自老师输入；知识与题面可追溯上传材料的具体页；补充剧情、过渡镜头和建议互动标为 AI 建议。来源在需要核对时展开，不在每行堆标签。不能给没有来源的数据伪造材料页码；老师修改后保留修改记录。

## 3. 从 HyperVideo 借什么

依据：[生产流程实测报告 §3](../../../04-用户与竞品分析/20260912-HyperVideo产品体验/HyperVideo生产流程体验与现有Agent改造结论_v2.md)、[博文工作台原始记录](../../../04-用户与竞品分析/20260912-HyperVideo产品体验/evidence/博文_工作台.txt)、[英语素材完成后的工作台记录](../../../04-用户与竞品分析/20260912-HyperVideo产品体验/evidence/英语_素材完成_分镜工作台.txt)，以及用户本次提供的配置截图。

| 实测可见的配置 | 对我方的判断 |
| --- | --- |
| 场景轴；当前场的目标、提示、素材、生成结果 | 借鉴稳定的场景位置，把规划和结果放在一起 |
| 画面提示内分镜、台词和 `@` 素材引用 | 借鉴素材与具体镜头的关联；老师默认看分镜卡与台词行，完整生成描述继续可见可编辑 |
| 单场生成、批量生成、候选版本 | 借鉴局部重做和批量操作；采用哪个版本必须明确 |
| 角色与背景作为共享素材，首尾参考帧可选 | 共享角色只维护一份；首尾帧与 IP、道具、场景参考分开表达 |
| 视频场、Frame 场与内场视频 | 借鉴一场内组合多种表达；我方混合场的产物必须包含可运行 H5，不能只交付有按钮画面的 MP4 |

HyperVideo 当时也有“先准备全局图片与音频，再进场景工作台”的阶段，不能说它已经实现本报告建议的全部流程。我们要进一步减少教师在阶段间搬运内容的感觉。

不照搬长参数表、手动音频起止秒数、Frame 类型比例。也不沿用“大纲和场景各自一套、看不出映射”的问题。章节可以包含多场，场内可以包含多镜头；短课件直接展示场景，避免强加章节管理。

## 4. 推荐流程与确认时机

```mermaid
flowchart LR
 A[输入需求与教学材料] --> B[确认整课结构与公共设置]
 B --> C[场景工作台：准备真实素材并细化本场方案]
 C --> D[审阅本场内容、素材、分镜或互动]
 D --> E[确认并生成所选场景]
 E --> F[同一场景内预览和局部修改]
 F --> G[整课连贯预览与交付]
 F --> D
```

1. **整课结构确认。** 系统先给出场景顺序、类型与具体内容摘要，并识别共享角色、风格、旁白。老师可拖动排序、增删场景、增减角色；确认后“准备场景素材”。输入框保留需求与材料入口，风格、音色集中在公共设置中，不重复选择。
2. **在工作台准备和审阅。** 系统从各场内容提取需要的共享与专用素材，生成后直接出现在使用它的场内；结合实际音频长度细化分镜和时长。老师看到真实图片、可试听音频、明确的画面描述，以及互动题面。没有产物的地方只显示待准备状态，不能用无关图片填满。
3. **确认当前制作方案再生成。** 提供“确认并生成本场”及“确认并生成所选场景”。默认可选择全部待生成场景，只需一次批量确认；缺少必需素材或有冲突的场景明确列出，不能悄悄跳过后宣称全课成功。已就绪的场景可以先生成，不必等所有场都准备好。
4. **生成直接回到同一场。** 系统完成本场的视频、必要的合成和 H5；老师逐场预览，修改内容或替换候选版本。生成期间也能查看其他场景；失败只重试相关任务。
5. **整课交付。** 系统按已确认场景顺序组装、检查衔接与资源，产出一个视频互动课件卡。老师检查完整课堂体验，再从原预览、插入、发布入口使用。最终场景目录与开始确认的是同一份结构。

这保留了用户之前要求的“先看真实素材与视频方案，再生视频”。变化是将两个确认对象合在场景上下文中审阅，生成图片/音频后不再跳转到另一份脱离场景的视频方案列表。

## 5. 工作台的具体布局

**对话保留需求、变更记录和进度摘要；点击方案进入宽幅场景工作台。** 不再向聊天流追加多张完整素材清单和视频清单。

```text
课件名称                         公共设置   全部素材   整课预览
──────────────────────────────────────────────────────────
场景目录                  当前场名称 · 内容类型 · 状态
01 开场                   本场内容：一两句具体说明，可编辑
02 情境引入   ← 当前      ┌ 场景方案 ────────────────────┐
03 操作练习               │ 视频分镜 / 互动内容，按呈现顺序 │
…                         │ 当前使用的真实素材随内容出现     │
12 回顾                   └────────────────────────────┘
可拖动排序                ┌ 本场预览 / 候选版本 ─────────┐
                          └────────────────────────────┘
──────────────────────────────────────────────────────────
已完成 x 场 / 待确认 y 场         确认并生成本场   生成所选场景
```

宽屏时本场方案与预览并排；较窄窗口改成上下布局，目录可收起。目录和编辑内容各自可滚动，底部操作固定。待生成时预览区清楚显示尚无成品，素材缩略图只作为方案依据。

不设置“目标 / 素材 / 分镜”三个必须来回切换的阶段页签。目标简述在顶部，场内按生成内容展开。全部素材是可检索的辅助入口；日常只显示当前场、当前镜头引用的部分。

### 按内容类型显示编辑项

| 场类型 | 本场方案里显示什么 | 完成后交付什么 |
| --- | --- | --- |
| 视频 | 一个或多个分镜：时长建议、画面描述、参考图、可选首尾帧、台词与说话人 | 可播放的场视频及采用版本 |
| 互动页面 | 页面内容/布局小样、题目与对象、操作方式、反馈、相关音频 | 可操作的 H5 场景；不要求首尾帧或视频分镜 |
| 视频＋互动 | 按呈现顺序放置视频与互动，例如“角色邀请 → 停留画面 → 学生拖动 → 结果反馈” | 可连续运行的视频＋H5 场景；各内容保留可编辑来源 |

视频分镜卡顶部并列显示首帧、尾帧，均可留空；下方放实际引用的 IP/背景/道具小图，再放画面描述和台词。参考图说明作用，例如“保持服务员形象”“菜单上方留白”；增加时从当前课素材库选择，默认不会把全部图片带入。

台词放在对应分镜或互动事件下，例如“镜头 2 · 服务员询问”“答错后的提示”。老师可更换真实音频，但不用填写技术时间轴。系统根据音频实长自动安排；超出镜头能力时提出延长或拆镜头建议，不静默截断。声音最终来自哪一条采用的音频必须明确，不能同时播放生成视频自带对白和外加相同配音。

完整生成描述继续常显；结构化内容与描述使用同一份数据。修改会影响角色引用、台词或时长时，先同步相应内容并提示冲突，不允许两套互相矛盾的配置进入生成。

## 6. 老师到底可以改什么：三个具体例子

以下是新界面的内容设计示例，不代表已生成新的图片、配音或场景。

### 悟空开场：互动页面

当前“建立西游识字主题与开始动机”可改为：**“显示《雨字头的秘密》标题和悟空，邀请孩子一起搬石认字；点击‘出发’开始故事。”**

界面直接提供标题、开场说明、角色/背景预览、按钮文案；不出现视频时长、首尾帧、学生参与的大段说明。老师改“出发”为“一起闯关”，结果就是按钮改变；想删去开场页，可以从目录删除，而非编辑抽象目标。

### 悟空邀请搬石：视频＋互动

场内呈现“悟空发出邀请”的真实视频与配音，然后是可拖石头的交互小样。老师直接改邀请台词、石头数量/位置、拖走后出现的字和反馈。系统负责停留背景、音频衔接、等待操作，不让老师描述底层播放事件。

若希望铁扇公主加入，在本场选择“添加角色”，填写她在剧情中的作用和台词，角色进入公共设置；随后准备真实形象与音色。系统列出受影响场景，老师采用后才更新，其他场景不自动塞入铁扇公主。

### 英语点餐：视频＋互动

本场内容：“服务员询问想点什么，学生选择餐品并组成 I’d like…；完成后服务员确认订单。”

老师能改服务员/儿童的台词、可选餐品、句型答案和错误提示；能看到餐厅、服务员、儿童这几项真实引用图。镜头描述明确“等待点餐时桌面为空”。如果后续画面要随着点餐结果变化，工作台应列出对应分支或可变 H5 内容；不能生成固定汉堡画面却宣称支持任意餐品。

纯知识讲解也适用同一结构，例如“水的三态”：直接编辑冰融化与水蒸发的画面、旁白和镜头顺序，没有人物则不强加角色，没有互动则不显示题目配置。

## 7. 场景数量、共享素材与改动范围

**12 场只是当前样例的编排结果，不应成为通用规则。** 场景围绕一段完整表达或任务组织；“邀请搬石”和“石头后出现汉字”可以是同场的两个状态，也可以按课堂节奏分场。模型需要把一个视频拆成两段时，优先作为场内镜头处理，不自动给老师增加两页。显著调整场景结构需回显原因和对应原内容。

公共角色/背景只生成和维护一份，场内保存引用与用途。老师在单场改共享素材时，应明确选择“仅用于本场”或“更新所有引用处”，并列出影响范围，避免一个局部修改偷偷改变整课。

| 修改 | 应更新的范围 |
| --- | --- |
| 修改一条台词 | 对应音频、使用它的镜头/互动、字幕及本场结果；时长变化时重新检查衔接 |
| 修改互动题目 | 对应 H5 与题目配音；若题面在视频里也出现，相关视频一并更新 |
| 替换共享角色图片 | 仅引用该版本的镜头与 H5；未涉及的场景保持已采用版本 |
| 调整场景顺序 | 编排及前后衔接检查；不无条件重生所有素材 |
| 修改整课风格或增加角色 | 提出受影响的场景和素材清单，确认后局部更新 |

没有真实图片/音频的引用标为待准备；生成后保存来源、版本、实际时长以及使用位置。成品缩略图来自当前版本实际渲染；旧截图不能用来代表修改后的场景。参考图是否可用、数量及用途要由接入模型的实际能力校验，不统一假定所有模型支持相同输入。

## 8. 代码改动判断

这是**中到大的流程与数据重构**，不能靠挪动卡片或换页签完成；现有媒体预览和编辑能力可继续复用。

| 部分 | 可复用 | 需要调整 |
| --- | --- | --- |
| 输入与公共设置 | 附件、教学内容、音色选择、风格控制 | 统一入口；角色安排与场内多角色台词联动 |
| 场景工作台 | 现有排序、类型、视频方案编辑、素材编辑、预览控件 | 合并分散的场景编辑与视频方案；增加具体互动内容编辑 |
| 数据 | 素材 ID、真实 URL、分镜引用、旧版本快照 | 增加场景方案/状态/产物版本；单条 `speakerId + dialogue` 改为台词列表；补内容来源与结构化互动 |
| 调度 | 现有素材依赖和失效检测思路 | 从全课单一 `phase/job` 改为场景及素材任务状态，支持批量、部分完成、局部失败与重试 |
| 交付 | 原课件结果卡、预览、插入、发布与历史版本 | 整课版本记录每场采用版本；视频、H5、配音、字幕和缩略图保持一致 |

依据：[数据模型](../src/data/videoCourseware/model.ts)、[规划与依赖](../src/data/videoCourseware/planning.ts)、[当前阶段调度](../src/components/VideoCourseware/workflow.ts)。

实施顺序建议：先确定场景方案与版本契约；再搭同一工作台并接入现有真实素材；随后改逐场/批量调度与整课组装；最后验证跨场修改、失败重试和多角色场景。新增角色必须有真实媒体后才能展示为完成。

当前仍是本地演示：素材使用真实样例，生成服务由前端模拟。重新组织界面不等于接入真实通用生产服务；原型生成后的复用文件不能作为改台词、换角色已经真实产出的证据。

历史会话继续按原流程快照显示；如升级草稿，创建新流程版本，并复制已确认内容及素材引用。已经交付的旧课件 HTML 不覆盖，来源课件和旧版本继续可用；新版课件独立生成。普通 H5 流程不随这次评审改写。

## 9. 本次执行结果与后续验收

本次已完成流程评审，主流程未重构。已修掉配音编辑左侧重复台词：左侧保留试听、使用位置与上传替换；右侧保留唯一可编辑文本。其他独立音频预览保持原样。

局部修复验证：TypeScript/Vite 构建通过；浏览器确认“找到洞口”的台词仅在右侧出现，试听能进入播放状态；未修改素材文件、历史 HTML 或线上服务。构建保留既有大包体提示。

后续重构至少覆盖这些真实验收：

- 场景目录从方案到结果保持对应，既能批量生成也能只重做一场。
- 同场两角色多句对白，音色、图片、镜头引用一致；纯讲解无角色也可完成。
- 图片/配音完成后在场内可审阅，确认前不会生成相关视频；首尾帧均空时仍能按实际模型能力生成。
- 只展示当前引用素材；上传替换、改台词、换共享角色只使相关场景待更新，旧版本仍可预览。
- 混合场交付真实可操作 H5；正确、错误、重试和分支均能运行，视频结束后衔接自然。
- 部分场景失败时其余产物保留，整课不能误报完成；新字幕与缩略图对应采用的场景版本。
