# 2026-11-18 验收：修改回显与新版交付

发送场景修改时，原来只回显场景数量和图片，逐场景文字被漏掉；发送仅保存草稿，还需回到旧卡片点“全部生成”，用户误以为已经开始生成。

## 现在的流程

1. 单场或多场修改按场景显示序号、名称、原话、对应参考图，图片可放大；整体补充意见单独展示。
2. 点击发送直接提交生成，处理中保留旧版可预览，禁用重复发送。
3. 成功后只新增一个版本，结果卡、预览标题、版本历史同步更新；历史结果不改写。
4. 保存失败或校验失败保留消息与草稿，可在课件卡片重试；失败不增加版本号。
5. 刷新后恢复修改原话、场景和图片，生成任务接续；历史旧格式消息回退显示原文，不再留空。

场景编辑弹窗的“保存”仍用于积累草稿；聊天输入区的“发送”代表提交生成，会合并当前已保存的修改。平台需要把图片URL和场景ID一起提交；不能仅传文件名。

## 验证与边界

- 浏览器回归：多场景、两张参考图、图片预览、生成中刷新、连续第2/3版、旧版快照保持、整体原话、无页面脚本错误。
- 状态回归：过期草稿拒绝、生成期防重复提交、合并资源修改；构建通过。
