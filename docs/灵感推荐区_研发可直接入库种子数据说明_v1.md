## 先说清楚：playways 的数据从哪里来

`playways` 不是 `creative-shrimp-suite-v1.0` 里天然存在的一张现成表，而是产品侧把创意虾里的多个模板来源整理成“首页可推荐玩法卡片”后的入库表。

真正的底层来源主要有三类：

1. `workspace/GAME-VAULT/templates-ready/INDEX.md`：快速通道总索引，里面有可用模板、游戏名称、年级、难度、风格、文件路径等信息。
2. `workspace/GAME-VAULT/templates-ready/action/INDEX.md`：动作竞技类模板索引，里面有 40 条动作玩法，并明确给出分类、核心机制、布局、游戏名、学科、知识点、难度、文件路径。
3. `workspace/GAME-VAULT/templates-ready/**.md` 以及少量 `10-INVENTORY/classroom/**.md`：具体玩法的完整提示词模板，包含“视觉框架、交互功能、题面数据”三步生成内容。

因此，研发入库时必须区分两类字段：

| 字段类型 | 字段 | 来源 | 前端用途 |
| --- | --- | --- | --- |
| 原始可追溯字段 | `sourceRefs` | 创意虾真实文件路径；如同目录存在同名 `_v数字.md`，取最高版本路径 | 仅研发追溯，不展示给用户 |
| 原始模板字段 | `templatePrompt` | `sourceRefs[0]` 指向的 markdown 全文；如同目录存在同名 `_v数字.md`，取最高版本全文 | 点击“套用玩法”后，折叠的“生成提示词预览”使用这个字段 |
| 半原始字段 | `ageText`、`typeLabel`、`subjectTags`、部分 `title` | 索引表、模板头部、文件名、模板正文 | 卡片筛选与展示 |
| 产品加工字段 | `category`、`shortDesc`、`cardTags`、`classFlow`、`replaceableContent`、`priority` | 产品基于模板内容做的首页展示整理 | 帮老师快速理解和筛选，不能声称是原始模板字段 |

关键结论：用户点击“套用玩法”后，真正喂给生成链路的玩法提示词必须用 `templatePrompt`，不能用 `shortDesc`、`cardTags`、`classFlow` 或旧的 `promptSnippet` 代替。`promptSnippet` 只保留为兜底摘要字段。

## 二、为什么首期选择这 41 条玩法

这 41 条不是随意挑选，也不是代表底层能力只有 41 个玩法。`templates-ready/INDEX.md` 中已经标注“可用模板 66+”，其中 `templates-ready/action/INDEX.md` 单独就有 40 条动作竞技模板。当前 41 条是从这些来源里筛出来的“首页首期推荐池”，选择依据如下：

1. 已沉淀为模板或半模板：优先选择已有明确玩法结构、课堂流程、可替换内容和来源文件的玩法，而不是一句话创意。
2. 老师能一眼理解：玩法名称和卡片说明能让老师快速判断“这个可以怎么用”，适合放在首页推荐区。
3. 可承接新知识点：每条玩法都能替换题目、词库、图片、发音、场景、奖励语等内容，适合“套用玩法后生成新课件”。
4. 覆盖首期核心场景：覆盖英语启蒙、语文识字、数学思维、益智谜题、排序拼图和通用闯关复习。
5. 覆盖不同年龄段：能支撑低龄启蒙、1-2年级、3-4年级、5-6年级四段筛选。
6. 不把题库规模等同于首页卡片数：Starfall 750 关、滑块/推箱子/谜题等更多底层素材，首期通过这些可理解玩法作为入口承接，后续再扩展更多卡片。

因此，41 条玩法是“P0 首页推荐池”，不是“全部创意库”。后续可以按使用数据、教研补充和真实生成效果继续扩容。

当前 demo 里的 `精选` 也不是原始分类，而是从这 41 条里按 `priority` 选出的默认推荐池。

## 三、玩法卡片入库表

### 3.1 首页卡片字段从哪里来

首页卡片上展示的内容都来自玩法卡片 `playways` 表，不是前端临时编写。但这里要特别注意：`playways` 表本身是产品整理后的入库表，并不是创意虾原始文件里已经存在的字段集合。

| 页面位置 | 入库字段 | 字段含义 | 示例 |
| --- | --- | --- | --- |
| 玩法名 | `title` | 老师看到的玩法名称 | 智慧跳跃-拼音启蒙 |
| 年龄 + 类型 | `ageText` + `typeLabel` | 适用年龄和互动方式 | 6-10岁 · 跳跃闯关 |
| 一句话说明 | `shortDesc` | 让老师快速判断这个玩法怎么玩 | 跳到正确拼音平台，跳错会触发温和提示。 |
| 课堂流程 | `classFlow` | 产品从模板“游戏流程/交互机制”中提炼的课堂步骤，卡片只展示前 4 步 | 播放目标音 → 选择平台 → 跳跃验证 → 星星奖励 |
| 标签 | `cardTags` | 适合套用的知识点/内容类型，帮助老师判断是否匹配自己的课 | 拼音、声母韵母、听辨 |
| 套用后的真实模板提示词 | `templatePrompt` | 点击“套用玩法”后生成提示词预览，供 AI 生成使用 | 完整 markdown 模板全文 |
| 套用后的摘要兜底 | `promptSnippet` | 仅当 `templatePrompt` 缺失时兜底使用 | 一句话玩法摘要 |
| 追溯来源 | `sourceRefs` | 研发/产品追溯用，用户侧不展示 | creative-shrimp-suite-v1.0/... |

因此，用户注释中提到的“跳到正确拼音平台…”、“播放目标音 → 选择平台…”、“拼音 / 声母韵母 / 听辨”分别来自：

- `shortDesc`
- `classFlow`
- `cardTags`

这些字段由产品基于 `creative-shrimp-suite-v1.0` 里的模板文件整理成用户可读文案；不是直接把原始模板文件名或内部描述暴露给老师。它们的作用是“帮老师看懂卡片”，不是最终生成提示词。

### 3.2 templatePrompt 字段要求

`templatePrompt` 是每条玩法最重要的生成字段，来源规则如下：

1. 先读取 `sourceRefs[0]` 对应的真实 markdown 文件路径。
2. 如果该文件所在目录存在同名 `_v数字.md` 文件，必须取最高版本号文件。例如同时存在 `001_障碍跳跳跳_拼音启蒙_蛋仔风_6-10岁.md` 和 `001_障碍跳跳跳_拼音启蒙_蛋仔风_6-10岁_v4.md` 时，取 `_v4.md`。
3. 将最终采用的最高版本路径写回 `sourceRefs[0]`，避免追溯路径和实际 prompt 不一致。
4. 将最终采用文件的 markdown 全文写入 `templatePrompt`。
5. 点击“套用玩法”后，折叠的“生成提示词预览”展示 `templatePrompt`。
6. 提交给生成链路时，把老师填写的“教学内容”和 `templatePrompt` 一起发送。
7. 如果某条数据临时没有 `templatePrompt`，才允许降级使用 `promptSnippet`，同时应记录数据缺失问题。

## 五、只读示例入库表

只读示例的产品口径需要区分“真实 HTML 示例数量”和“玩法卡片可查看示意数量”：

1. 首期真实 HTML 示例为 4 条，用于覆盖英语图文互动、听音跟读、单词拼写、闯关答题节奏四类基础互动结构。
2. 首页 41 条玩法卡片都应该有“看玩法示例”入口，不能因为 `exampleId` 为空就隐藏，否则老师会觉得部分玩法不可理解、不可预览。
3. 对于 `exampleId` 为空的玩法，前端或服务端需要按玩法结构做同类示例兜底映射。例如：英语类兜底到英语图文或拼写示例；拼音/听辨类兜底到听音跟读示例；其他闯关/谜题类兜底到闯关答题节奏示例。
4. 示例弹层必须明确提示：这是玩法效果示例，套用后会替换成老师自己的教学内容。避免老师误解为只能生成示例里的水果、动物或数学题。
5. 后续如果研发/教研补齐更多真实 HTML 示例，只需要更新每条玩法的 `exampleId`，不影响首页卡片结构。

## 六、首页实现口径

1. 分类 tab 使用 JSON 中的 7 个配置：精选、闯关挑战、英语启蒙、语文识字、数学思维、益智谜题、排序拼图。
2. 年龄筛选使用 4 个配置，并额外提供“全部年龄”：低龄启蒙、1-2年级、3-4年级、5-6年级。
3. 精选 tab 首期可按 `priority` 取前 16 条，首页每屏展示 8 条，通过“换一换”切换下一批。
4. 其他 tab 按 `category` 过滤，再叠加年龄段过滤。
5. 卡片默认展示：年龄 + 玩法类型、玩法名、短说明、课堂流程前 4 步、3 个标签、看玩法示例、套用玩法。
6. 套用玩法后，输入框回显结构化需求草稿，而不是简单拼一句提示词。
7. 切换玩法时，应保留老师已经输入的教学内容，只覆盖 `<已套用玩法>` 结构块。

### 6.1 精选逻辑

`featured` 不是一个真实内容分类，而是首页默认推荐池。当前 demo 逻辑为：

1. 从 `playways` 全量 41 条里按 `priority` 从高到低排序。
2. 取前 16 条作为精选推荐池。
3. 首页每屏展示 8 条。
4. 点击“换一换”后展示下一批 8 条；如果到末尾则循环。
5. 年龄筛选仍然生效：先取精选池，再按年龄段过滤。

因此，“精选”不是简单拿原数组前 8 个，而是按 `priority` 取前 16 个，再分批展示。

### 6.2 分类配置映射

页面显示 7 个 tab，但只有 6 个真实内容分类。`featured` 是虚拟精选 tab，其余 6 个才对应玩法的 `category` 字段。

| 页面 tab | 数据 id | 是否真实内容分类 | 过滤逻辑 | 主要覆盖内容 |
| --- | --- | --- | --- | --- |
| 精选 | `featured` | 否 | 按 `priority` 取推荐池，不按 `category` 过滤 | 首页默认推荐、高复用玩法 |

## 八、入库提醒

1. `sourceRefs` 仅研发和产品追溯使用，用户侧不展示。
2. `templatePrompt` 必须作为推荐玩法 prompt 的注入片段；`promptSnippet` 只做摘要兜底。
3. 如同目录存在同名 `_v数字.md` 文件，`sourceRefs` 和 `templatePrompt` 必须取最高版本，不取无版本号旧文件。
4. 多个玩法可以共用同一个示例，但弹层文案必须说明“套用后会替换为你的教学内容”。
5. `exampleId` 为空不代表玩法没有示例入口，而是需要前端/服务端做同类示例兜底映射。
6. `category`、`cardTags`、`classFlow` 等字段是产品加工字段，研发可以直接入库，但不能把它们理解为创意虾原始标准字段。
7. 这份数据是首页 P0 推荐池种子数据，不代表底层题库只支持这些内容；Starfall 750关、滑块120关、推箱子60关等题库通过 `sourceRefs` 后续调用。
