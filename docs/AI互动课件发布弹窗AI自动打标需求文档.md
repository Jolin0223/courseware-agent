# 一、项目背景

## 1.1 项目背景

AI互动课件生成后，需要通过发布弹窗沉淀到集团资源库、校本资源库或个人资源库。资源入库时需要完成标签标注，便于后续在 iTeach 资源库中检索、筛选、复用和做学情报告关联。

当前发布弹窗已支持选择发布范围、学校、课件名称、科目、年级、知识点/校本标签和内容标签。本次需求是在现有发布弹窗内新增 AI 自动打标能力，降低老师和教研员手动选择标签的成本。

## 1.2 现状/问题

| 问题 | 说明 | 影响 |
| --- | --- | --- |
| 手动选择知识点/校本标签成本高 | 老师需要从标签树中自己找匹配标签 | 发布链路变长，容易漏选或错选 |
| 集团标签和校本标签来源不同 | 集团资源库使用集团知识点标签；校本资源库使用校本标签 | 如果不按资源库区分，容易拉错标签树 |
| 校本标签会被分校修改 | 校本标签由集团知识点复制初始化，分校教研员可以修改 | 每次打标都需要拉取最新校本标签树 |
| 多权限账号无法提前确定标签树 | 一个用户可能同时有集团权限、多个分校权限或多个科目权限 | 系统不能在点击发布前提前决定使用哪棵树；若在弹窗内频繁切换发布范围、学校、科目后自动打标，会造成 AI 资源浪费 |
| 用户可能人工改过 AI 结果 | 用户删除、新增、修改标签后，可能又想重新 AI 打标 | 如果直接覆盖，会丢失人工修改 |
| 标签源头可能被删除 | 已选知识点/校本标签可能已被 iTeach 删除 | 如果继续发布，会产生无效标签数据 |
| 内容标签缺少范围定义 | 当前内容标签只知道“玩法、视觉风格”大方向 | AI 输出容易发散，不利于资源检索和运营维护 |

## 1.3 解决方案

**一句话描述方案：**在发布弹窗标签标题右侧始终展示 `AI智能打标` 按钮；系统按发布范围、学校、科目拉取对应标签树，并由 AI 推荐知识点/校本标签和内容标签。若用户人工修改后再次打标，需要二次确认；若已选标签在 iTeach 源头被删除，则置灰展示为失效标签并阻断发布。

| 发布范围 | 标签展示 | AI 打标来源 | 按钮规则 |
| --- | --- | --- | --- |
| 集团资源库 | 知识点标签 + 内容标签 | 集团知识点树 + 课件内容 | 始终展示 `AI智能打标` |
| 校本资源库 | 校本标签 + 内容标签 | 最新校本标签树 + 课件内容 | 始终展示 `AI智能打标` |
| 个人资源库 | 内容标签 | 课件内容 | 始终展示 `AI智能打标`，只刷新内容标签 |

## 1.4 核心规则

| 规则 | 说明 |
| --- | --- |
| 按钮始终展示 | 三类资源库均展示 `AI智能打标` 按钮，区别是集团/校本会处理资源标签，个人只处理内容标签 |
| 单权限自动预打标 | 若用户只有 1 条可用标签树权限，打开弹窗后系统自动先打一次，但按钮仍保留 |
| 多权限手动触发 | 若用户有多条权限，点击发布前不自动打标；打开弹窗后也不因上下文变化自动打标，用户确认发布范围、学校、科目后点击按钮 |
| 多权限自动打标边界 | 本期不做“上下文稳定后自动打标”；该能力作为 P1 后续优化评估 |
| 人工修改后二次确认 | 用户新增、删除、修改任一标签后，再次点击 AI 打标需二次确认 |
| 成功后替换 | 重新 AI 打标成功后，整体替换当前标签结果 |
| 失败后保留 | AI 打标失败时，不覆盖用户当前标签 |
| 失效标签阻断发布 | 集团/校本标签若在最新标签树中不存在，置灰展示为 `已失效`，确认发布时阻断 |

| ![AI自动打标完整流程图](assets/ai-auto-tag-detail-flow.svg) | **3-3 多权限自动打标后续评估**<br>* 本期不做：多权限场景不做“上下文稳定后自动打标”。<br>* P1 可评估方案：用户在发布弹窗内选定发布范围、学校、科目后，若 800ms-1500ms 内未继续切换，且当前上下文没有打标结果，可自动触发一次 AI 打标。<br>* P1 前置条件：需要有明确的防抖、取消、缓存命中、调用次数限制和失败降级策略。<br>* P1 风险：如果用户只是短暂停留或误选上下文，仍可能造成无效 AI 调用，因此不纳入本期 P0。 |
| ![AI自动打标完整流程图](assets/ai-auto-tag-detail-flow.svg) | **4-1 人工修改后再次 AI 打标**<br>* 人工修改定义：用户新增、删除、修改任一知识点标签、校本标签或内容标签，均视为用户已人工修改。<br>* 再次点击：若用户已人工修改过标签，再次点击 `AI智能打标`，需先弹二次确认。<br>* 二次确认文案：`重新打标会覆盖当前已选标签，确定继续吗？`<br>* 二次确认按钮：`取消`、`重新打标`。<br>* 点击取消后：关闭二次确认弹窗，不执行 AI 打标，保留当前标签。<br>* 点击重新打标后：进入按钮 loading；loading 期间先保留当前标签，不提前清空。<br>* 打标成功后：用新的 AI 推荐结果整体替换当前标签。<br>* 打标失败后：保留当前人工修改结果，toast 提示：`AI智能打标失败，已保留当前标签，请稍后重试或手动修改。` |
| ![AI自动打标完整流程图](assets/ai-auto-tag-detail-flow.svg) | **5-1 源头标签被删除后的失效标签规则**<br>* 触发时机：打开发布弹窗、恢复本地缓存、切换发布范围/学校/科目、点击确认发布前，均需用最新标签树校验已选知识点/校本标签。<br>* 若源头仍存在：标签正常展示，允许发布。<br>* 若源头不存在：标签仍展示在已选区，但置灰，并追加 `已失效`。<br>* 失效标签操作：用户可以删除失效标签；失效标签不可在下拉树中再次选中。<br>* 重新打标：用户点击 AI智能打标后，系统按最新标签树重新推荐；若新结果不包含失效标签，则自动移除失效标签。<br>* 发布校验：若集团/校本标签中仍存在失效标签，点击确认发布时阻断，toast 提示：`当前标签已失效，请删除后重新选择标签`。<br>* 内容标签：内容标签不依赖 iTeach 标签树，不存在源头删除导致的失效状态。 |
| ![发布弹窗标签区原型](assets/ai-auto-tag-publish-modal.svg) | **6-1 内容标签推荐范围**<br>* 内容标签定位：用于描述课件内容形态，不替代知识点标签或校本标签。<br>* 推荐数量：默认推荐 3-5 个短标签。<br>* 推荐维度：玩法机制、互动能力、视觉主题、学习活动。<br>* 本期不做：课堂用途类标签暂不纳入内容标签范围，避免和运营分类混淆。<br>* 示例标签：`闯关玩法`、`语音跟读`、`果园视觉风格`、`配对玩法`、`拼写练习`、`颜色认知`、`数感练习`。<br>* 示例规则：若课件包含关卡/挑战/通关逻辑，可推荐 `闯关玩法`；若课件包含跟读、朗读、口语或语音评测，可推荐 `语音跟读`；若课件主场景为果园、水果、Fruit Garden，可推荐 `果园视觉风格`。 |

# 五、数据口径需求

## 5.1 标签来源口径

| 标签类型 | 什么时候拉取 | 拉取依据 | 使用规则 |
| --- | --- | --- | --- |
| 集团知识点标签 | 集团资源库打开弹窗、AI 打标、发布前校验 | 当前科目 | AI 只能从当前科目知识点树中选择 |
| 校本标签 | 校本资源库打开弹窗、AI 打标、发布前校验 | 当前学校 + 当前科目 | 每次打标和校验均拉取最新校本标签树 |
| 内容标签 | AI 打标时 | 课件名称、课件内容、科目、年级、互动结构 | 可由 AI 生成，也可由用户人工修改 |

## 5.2 前端缓存口径

| 缓存内容 | 缓存粒度 | 使用场景 | 注意 |
| --- | --- | --- | --- |
| 知识点/校本标签推荐结果 | 当前课件 + 发布范围 + 学校 + 科目 | 多权限用户切回已打标上下文时恢复 | 恢复前必须用最新标签树校验，找不到的展示为失效标签 |
| 内容标签推荐结果 | 当前课件 + 发布范围 + 学校 + 科目 | 多权限用户切回已打标上下文时恢复 | 从集团/校本切到个人资源库时不清空 |
| 人工修改状态 | 当前弹窗会话 | 判断再次 AI 打标是否需要二次确认 | 用户任意新增、删除、修改标签后置为已人工修改 |

## 5.3 发布保存口径

点击确认发布时，需要保存用户最终确认后的标签结果：

| 发布范围 | 保存内容 | 发布前校验 |
| --- | --- | --- |
| 集团资源库 | 课件基础信息、科目、年级、知识点标签、内容标签 | 知识点标签非空，且不存在失效标签 |
| 校本资源库 | 课件基础信息、学校、科目、年级、校本标签、内容标签 | 校本标签非空，且不存在失效标签 |
| 个人资源库 | 课件基础信息、科目、年级、内容标签 | 不校验知识点/校本标签，内容标签为空也允许发布 |

# 六、待确认问题/本期不做范围

## 6.1 待确认问题

| 问题 | 建议方案 | 影响 |
| --- | --- | --- |
| AI 打标失败时是否允许无知识点/校本标签发布 | 建议仍沿用必填校验，失败后用户可手动选择 | 影响发布成功率和资源规范 |
| 校本标签管理保存后是否自动刷新当前弹窗标签树 | 建议本期点击 AI 打标或发布前校验时重新拉最新树，不做实时刷新 | 降低本期复杂度 |
| 内容标签是否需要统一运营后台维护词库 | 建议本期先由 AI 推荐 + 用户自定义，后续再做词库治理 | 影响后续检索一致性 |
| 多权限是否做上下文稳定后自动打标 | 建议本期不做，P1 再评估防抖、取消、缓存和调用次数限制 | 影响 AI 调用成本和前端状态复杂度 |
| 个人资源库是否未来也需要知识点标签 | 建议本期不做，后续如学情报告需要再评估 | 影响个人资源报告能力 |

## 6.2 本期不做范围

| 不做项 | 说明 |
| --- | --- |
| 不做独立 AI 打标弹窗 | 本期只在标签标题右侧展示按钮，不新增二级打标弹窗 |
| 不做大面积权限说明面板 | 不展示当前标签树、账号权限数量等技术信息 |
| 不做多权限自动触发打标 | 多权限用户进入发布弹窗后，需点击 `AI智能打标` 按钮；切换发布范围、学校、科目不自动调用 AI |
| 不做内容标签运营词库后台 | 本期仅定义推荐范围和前端编辑能力 |
| 不做课堂用途内容标签 | 本期内容标签先聚焦玩法、互动能力、视觉主题、学习活动 |
| 不做埋点需求 | 如需埋点，单独补充埋点需求文档 |
| 不做真实接口协议细化 | 本 PRD 写产品口径，接口字段由研发联调时确认 |

# 七、验收标准

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 集团资源库按钮展示 | 选择集团资源库 | 知识点标签标题右侧展示 `AI智能打标` |
| 校本资源库按钮展示 | 选择校本资源库 | 校本标签标题右侧展示 `AI智能打标` 和 `编辑校本标签` |
| 个人资源库按钮展示 | 选择个人资源库 | 内容标签标题右侧展示 `AI智能打标` |
| 单权限自动预打标 | 单权限用户打开发布弹窗 | 系统自动回填推荐标签，且按钮仍保留 |
| 多权限手动打标 | 多权限用户点击 AI智能打标 | 按当前发布范围/学校/科目回填标签 |
| 多权限切换上下文 | 多权限用户切换集团/校本、学校或科目 | 不自动触发 AI 打标；若该上下文已有缓存结果则恢复，否则等待用户点击按钮 |
| 打标 loading | 点击 AI智能打标 | 按钮文案变为 `AI智能打标中`，按钮内转圈，不可重复点击 |
| 打标完成 | AI 打标成功 | toast提示：`AI智能打标完成~如有问题可人工修改。` |
| 人工修改后二次打标-取消 | 人工修改标签后点击 AI智能打标，再点取消 | 不执行打标，保留当前标签 |
| 人工修改后二次打标-确认成功 | 人工修改标签后点击 AI智能打标，再点重新打标 | 打标成功后用新 AI 推荐结果整体替换当前标签 |
| 人工修改后二次打标-失败 | 人工修改标签后确认重新打标，但 AI 打标失败 | 保留当前人工修改结果，并 toast 提示失败 |
| 源头标签失效展示 | 已选标签在最新 iTeach 标签树中不存在 | 标签置灰展示，并追加 `已失效` |
| 源头标签失效发布 | 存在失效知识点/校本标签时点击确认发布 | 阻断发布，toast提示：`当前标签已失效，请删除后重新选择标签` |
| 个人资源库展示 | 从校本资源库切换到个人资源库 | 隐藏校本标签；内容标签不清空 |
| 发布校验 | 集团/校本标签为空时点击确认发布 | 分别 toast 提示：`请选择知识点标签` / `请选择校本标签` |
