# 整课交付后按场景修改：交互规划

2026-09-15｜**已在 4186 旧版原型实现并验证**｜`codex/wukong-video-h5-agent-demo`。

## 当前交互

**结果卡每场的两个按钮固定为“预览”和“修改”。** 修改复用当前场景大弹窗；老师从具体场景开始调整，不必先判断应该去图片、音频还是视频资源库。

原“编辑资源”保留为全课素材管理入口，适合替换全课角色形象、统一音色等跨场调整。它不再承担高频单场内容修改的主要入口。

## 操作流程

结果卡选择某场「修改」→ 打开本场编辑弹窗 → 修改内容、分镜或素材 → 查看影响范围 →「生成本场新版本」→ 新旧场景对比 →「采用并更新整课」→ 整课新版本。

- 弹窗沿用本次实现的内容与引用素材布局，不另造工作台。
- 只改场景名称等展示信息时直接更新草稿，不重复生成媒体。
- 生成期间原整课继续可用，其他场景可以预览；当前场显示“新候选制作中”，不把已交付版本标为未完成。
- 新候选完成前不替换旧场景；失败只重试本次未完成任务，放弃则保留原课。
- 采用候选后，更新整课内相应场景及衔接，形成下一版。已发布版本不会自动替换，仍通过现有发布流程更新。

## 修改范围如何确定

| 修改 | 默认处理 | 保存前说明 |
| --- | --- | --- |
| 本场内容、互动规则、布局描述 | 只重做本场页面；需要动态画面变化时才重做视频 | 本次将更新的页面和视频 |
| 本场视频动作、镜头、分镜描述 | 重做选中的视频及引用它的场景合成 | 视频段数与场景名称 |
| 本场配音台词、音长 | 重做对应配音，复核视频时长、字幕和口型依赖 | 哪些配音和视频需要更新 |
| 共享图片或共享配音 | **默认仅本场生效**，为本场建立独立引用 | 原素材还用于哪些场景 |
| 明确选择同步更新共享素材 | 展示全部受影响场景，再统一生成候选 | 必须列出场景名称，不能悄悄扩大范围 |

仅本场修改建立独立资源引用，保留共享原资源；播放配置按场景解析独立引用，切换到其他场景恢复原素材。需要重做哪些视频应由实际引用与生成输入变化判定，不按“改了音频就把全课重做”处理。

## 版本与入口规则

- 最新整课版本开放“修改”；历史版本提供“基于此版创建草稿”，不直接回写历史快照。
- 同一场已有未完成候选时进入现有草稿，不重复启动第二个相同任务。
- 采用前对照“当前版本 / 新候选”，允许试听、单场预览、返回继续改或放弃。
- 采用过程中重新核对当前整课版本，避免另一次编辑把刚完成的修改覆盖掉。
- “更新整课”复用未受影响的产物，只重新处理必要衔接；旧课件 HTML 和已发布版本保留。

## 验收重点

1. 每场直接进入统一编辑弹窗，不必绕到全课资源管理。
2. 修改第三场时，另外十一场可以继续预览且内容不变。
3. 修改共享角色图默认只影响当前场；选择全课同步时明确列出范围。
4. 新候选生成失败，原整课和原单场均可继续使用。
5. 取消、放弃候选不改变旧课；采用后创建新整课版本，历史版本仍可打开。
6. 修改后的视频、配音、页面合成依赖正确，不能在视频未完成时把混合场景标为可用。

## 实现与验证

- 最新结果卡每场直接打开统一大弹窗，内容与素材在同一事务内修改；先保存草稿，再确认更新范围。
- 草稿、候选和局部进度保存在项目中，刷新可继续；同场复用现有草稿。关闭弹窗时制作继续，放弃则删除本次候选。
- 仅修改名称不重新生成媒体。视频改动按实际输入、素材与音频依赖判断；混合场景等待本场全部视频和页面完成，再完成合成。
- 共享素材默认建立本场独立引用；选择同步时列出受影响场景。当前版本与新候选各自使用自己的播放配置，采用前不更新原版。
- 采用前校验整课版本。另一场先采用后，已有候选会标为待合并；合并只重放修改字段，保留新版本的其他场景和资源引用。
- 历史行也使用“修改”按钮，进入后提供“基于此版创建草稿”；只取历史版这一场，其他场景以最新整课为准。

## 原型与历史边界

本地原型验证的是编辑、候选和版本采用流程。图片、音频与视频生成仍回用示例媒体，不调用在线生成服务；上传文件可以实际替换预览素材。修改互动内容的候选使用已有文字页面适配器，不代表已生成新的完整精品画面与交互；修改视频提示词也不会真实重拍视频。

原课的 HTML 快照、历史版本与发布记录不回写，不自动发布新版本。只给产品原型的 `lesson-v5.html` 增加按场景解析素材的兼容配置；旧配置保持原行为，独立精品课件 `index.html` 和 `lesson-v4.html` 不改。4187 停用分支保持原样，所有修改仅保存于本地旧版分支。
